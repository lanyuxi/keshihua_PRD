# Visual PRD 4.1.8 原型文案编辑验证

验证日期：2026-10-19。基于本仓库 4.1.7 增加中间原型文案编辑，继续保留原 4.0.2 与 2.2.1 能力。未读取或修改用户的软件授权系统项目。

## 交互与保存

- 中间工具栏在“下载”前增加“编辑”，开启后显示“完成编辑”。点击 HTML 文案打开就地编辑框，输入后立即提交现有保存队列；退出后恢复业务交互。
- 只更新文本节点或显示属性，保留父节点、图标、事件、锚点、字段绑定和下拉 value；左右两栏继续使用各自编辑入口。
- 标题、表头、按钮、禁用按钮、嵌套文字、详情页、弹窗、选中下拉选项和 placeholder 可修改；普通表单输入值不作为界面文案写回。
- 覆盖记录内嵌到评审 HTML，切页、重新载入、刷新及从新路径重开后应用；编辑开关、编辑框和临时高亮不永久保存。
- 单页与全部页面 ZIP 从原业务源码生成，只附带必要的文案应用逻辑，不输出编辑框、产品说明或页面标注；不序列化 iframe 当前 DOM。

| --- | --- |

| ZIP 所有入口 | 实际解压两页，CRC 通过；分别打开列表、详情入口，验证改过的文案、跨页导航、新增表单提示与原业务操作；源文件不含编辑器或评审数据 |

| 事件链 | 编辑状态下鼠标抬起、键盘与提交事件链被拦截；编辑框内部仍能真实聚焦、选择和输入，原生 dialog 保持模态；退出编辑恢复原行为 |
| 独立代码复核 | 独立只读复核在当前源码上重新操作 Chrome，确认业务捕获事件与原生模态框两项问题已关闭，无阻断项 |

浏览器下载测试使用独立文件名，避免不同回归并发覆盖下载 ZIP 或重开页面。文件句柄自动化使用 Chrome 真实 OPFS 与 writable stream，选择器返回句柄为测试替身；未将其称作本版本新做的系统文件选择器人工操作。原生选择器路径的先前操作见 [4.1.7 验证记录](verification-4.1.7.md)，本版沿用相同磁盘授权与写入逻辑。

## 保留与边界

原包 51 个文件全部存在，40 个逐字节一致；新增 10 个文件，总计 61 个。原包 `_meta.json`、原作者署名和现有品牌图保留。“三栏评审 ↔ 浮动标注”的 `setMode` 函数逐字未改。仓库继续只保留此前用户指定的界面截图。

- 修改是评审 HTML 中的文案覆盖，不反向修改接口字段名、产品模型、PRD、流程图或原型源文件。
- 覆盖通过稳定定位与原文校验应用，不把已变化的业务数据强行替换回旧文案。图片、Canvas 内的文字以及不可访问的跨域页面不属于 HTML 文本。
- 首次磁盘写回仍须选择当前已有 HTML 并授权；仅浏览器草稿不代表磁盘文件已保存。
- 保留原包 iframe sandbox 提示及原构建器 Python 转义 SyntaxWarning，未扩大修改范围。
