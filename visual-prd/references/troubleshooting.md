# 故障处理协议

当用户报告可视化 PRD 问题时，无需用户分步引导：

1. 先用不超过 10 行说明涉及模块、最可能根因和拟修改文件。
2. 从业务规则或数据源头修复，保持单一数据源，精确命中问题；不以渲染层补丁掩盖上游错误。
3. 修复后执行 [相关自检项](interaction-checklist.md)，输出结果表。
4. 任何适用项不通过，继续修复并复测；无法确认的项如实标记“未验证”。

常见问题：

- **编号不一致**：编号只来自 `order` 字段，禁止用 `index` 计算；同一时刻可见的标注不得重号或跳号。
- **表格不渲染**：启用 GFM 表格扩展，渲染前确保表格前后有空行。
- **点击误触发**：handler 用 `closest('.anno-dot')` 校验，返回 `null` 则直接 `return`。
- **标注内容对不上**：内容必须来自 PRD 或标为“待确认”，不得补写未经证实的业务规则。
- **右栏有标注、原型所有页面都没有圆点**：先看主交付是否由本 Skill 构建，再核对原型 `body[data-anno-page]`、运行时 `getState().pageId` 与标注 `pageId` 是否一致。只要当前页 ID 被容器默认值覆盖，所有锚点都会被按页过滤；修正后重建，并分别复核首页和切页后的圆点。`PASS_STATIC` 不能代替这一步。
- **交互不生效**：依托 `prototype-runtime.js` 的 `data-action` 机制修复，不手写第二套独立交互逻辑。
