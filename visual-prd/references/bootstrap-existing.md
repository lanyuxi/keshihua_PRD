# 现有原型从零建立标注

适用：用户提供了普通离线 HTML 原型，却没有 `annotations.json`、`data-anno`，或两者只有其一。增强模式的构建脚本负责**装配已有标注**，不会凭空理解业务，也不会自动猜出标注该挂在哪个控件上。先完成下面的准备，再运行 `build-review.py`。

## 1. 盘点可核对的材料

先确认原型入口 HTML、关联的本地资源、页面切换方式，以及 PRD／业务规则／验收条件是否存在。优先挑用户真正要评审的页面，不要给每个装饰元素都加圆点。

若用户给的是 Axure 导出目录，先找目录内已有的 `visual-prd.project.json` 或已适配工作副本。`index.html`／`start.html` 通常只在 iframe 中载入业务页，不能把这一个入口文件复制进离线容器后宣称整个项目已增强；需要保留多文件资源和页面路由，或按业务页制作自包含的评审副本。

- 有 PRD 或规则：标注说明引用能定位的原文。冲突按“待确认”处理，列出来源，不擅自选一个答案。
- 只有原型：可以为页面上看得见、代码中能核对的操作写界面说明；业务规则留空或写“待确认”。为构建器创建 `prd.md`，标题明确为“原型观察记录（待产品确认）”，只记录已观察事实，不伪装成正式 PRD。
- 原型的交互无法离线运行、业务页面由远端服务渲染，或无法定位稳定元素时：说明需要用户提供静态导出或项目源码；不要交付没有圆点的空评审页。

## 2. 先列标注计划，再改工作副本

对每条候选标注记录：页面 ID、页面上真实存在的元素、可核对的说明来源、标注标题与内容、作用域。只选有稳定定位点的真实元素；同一个可见视图内编号从 1 连续排列。

将原型复制到项目工作目录，再在**副本**的对应元素上添加 `data-anno`。例如：

```html
<button id="save-draft" data-anno="save-draft">保存草稿</button>
```

对应创建 `annotations.json`：

```json
[
  {
    "id": "save-draft",
    "order": 1,
    "pageId": "edit",
    "title": "保存草稿",
    "body": "页面显示“保存草稿”入口；保存后的状态与权限待产品确认。",
    "businessRules": [],
    "scope": {"type": "page", "id": "edit"}
  }
]
```

这里的“保存后的状态与权限待确认”是缺失项提示，不是擅自确认业务规则。标注对象的完整字段、编号与 Tab／弹窗规则见 [标注指南](annotation-guide.md)。

若元素由 JavaScript 动态渲染，应该在其**渲染模板或组件副本**上添加稳定的 `data-anno`，不能只改初始 HTML 的空挂载容器。一个标注 ID 在同一原型中只出现一次。多页面原型还要保证切页时更新 `body[data-anno-page]`；如果当前结构做不到，先处理页面识别，再装配。

## 3. 建清单并构建

从 `assets/project-manifest-template.json` 创建项目清单，设置 `mode: "enhance"`，让 `inputs.prd`、`inputs.prototype`、`inputs.annotations` 分别指向上述 PRD／观察记录、已加锚点的原型副本、标注数据。所有路径相对于清单文件。然后运行：

```bash
python3 scripts/build-review.py visual-prd.project.json
```

如果报“零标注”或“标注缺少原型锚点”，回到第 2 步修复数据和元素的对应关系，不得用空数组或假锚点绕过。构建成功后，以 `build-report.json` 的 `primary_artifact` 为主交付。

## 4. 验证“有标注效果”

静态检查只能确认数据和锚点存在。还要在真实浏览器打开主交付，至少对一条标注核对：页面上的编号圆点出现；点击能弹出对应说明；右侧条目能定位到同一个元素；切换三栏和浮动标注后仍能定位；原型本来的按钮和弹窗仍能工作。多页面、Tab、抽屉和弹窗各抽一条。未完成浏览器核对时，只能说“静态装配通过”，不能说“标注效果已验证”。

## 交付说明

说明这次标注是“依据已有材料建立”还是“依据原型观察建立”；列出仍待产品确认的规则。交付主评审页、构建报告和所用工作副本；用户原文件保持不动。
