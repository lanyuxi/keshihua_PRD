# 指标与埋点定义

仅当本次需求需要衡量成效或采集行为时使用。指标与埋点属于产品需求定义的一部分，不是独立的分析或发布门禁。先写清产品目标，再定义可计算的指标，最后定义真正需要的新事件；已有可信数据源可以直接引用，不必为了填表虚构埋点。

## 最小定义链

`产品目标 → 成功指标 → 计算口径 → 数据来源/事件 → 埋点验收条件`。

- 指标说明公式、分子和分母（非比率指标的分母为 `null`）、统计窗口、去重口径、数据来源和验收条件。
- 事件说明唯一名称、准确触发条件、属性名称与类型、是否必填、取值含义和验收条件。事件发生的页面或原型锚点有依据时再填写。
- 不确定的公式、窗口、身份合并或数据源标记 `PENDING`，在 `open_questions` 中写明具体问题；不得把“待确认”指标标为可计算。
- 与需求交接时，指标 ID 使用 `METRIC-###`，在 `handoff.json` 的 `links[]` 中建立需求到指标的引用；不要在指标文件中维护第二份需求 ID 映射。事件使用独立的 `EVENT-###`。

## 产物与验证

在 PRD 的“数据与埋点”板块给人阅读的定义，同时从 [指标模板](../assets/metric-plan-template.json) 生成独立的 `metrics.json`。两者表达同一口径，修改时一起更新，不把未确认内容写成已确认。机器可读结构见 [Schema](metrics.schema.json)。

```bash
python3 scripts/validate-metrics.py <metrics.json>
```

若本期确实不涉及指标，设 `applicability: "NOT_APPLICABLE"` 并写明原因。尚未决定是否需要指标时设 `PENDING` 并记录待确认问题；两种情况都不要生成虚假的成功指标。
